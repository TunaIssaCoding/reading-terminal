# Reading Terminal — design

## Boundary and data model

The public site contains code, 44 explicitly fictional demo records, and a browser-produced encrypted `vault.json` after setup. Private reading data is fetched directly from GitHub; no proxy, analytics, remote scripts, or server is involved. Normal vault credentials live in memory, optionally restored from an encrypted IndexedDB device record. `localStorage` stores theme, pane preferences, namespaced shelf collapse choices, non-secret connection defaults, and a synchronous pending-write recovery journal. Only the explicit legacy manual-token connection persists a token in localStorage. IndexedDB stores a separate content cache, durable write queue and pre-v2 backup for each owner/repository/branch; demo data uses `demo:v2`.

`library.json` is bot-owned metadata. `user/state.json` is an article-id map of `progress` (`new|reading|finished|let_go`), fractional `position`, `starred` (Keeper), `triaged_at`, `progress_changed_at`, `last_opened_at`, and per-field `_timestamps`. `user/queue.json` contains `{queue:[ids],arrivals_since:ISO}`; queue membership/order are editable, capped at ten. `user/notes/<slug>.json` contains long_notes, highlights, links, hidden_links and updated_at. Highlights retain anchoring fields, optional `still_agree_at` local date and deletion tombstones. Has notes is derived, never persisted. Note edits cannot change progress. `bot/editions/<YYYY-MM-DD>.json`, other bot files and library metadata remain read-only.

With no article link, the app reopens the most recently opened article whose progress is Reading; otherwise it waits for a choice. A deep link wins article selection. Opening an article records `last_opened_at` and moves New to Reading. Scroll position is saved on a 750 ms leading/trailing throttle while Reading and restored on reopen. At 90%, a per-article tracker marks Finished and offers six-second Undo to Reading; it re-arms only below 90%. `r` toggles Finished/Reading with Undo; `s` toggles Keeper. With no article, all article header actions are hidden and `r`/`s` are inert. (Edition, Arrivals, Up next and shelves were removed on 26 Nov 2026.)

### Migration boundary

`init()` loads library, original state, metadata and queue before exposing state to the UI. Legacy unread/read/commented map to new/finished/reading-or-finished; manual Commented is finished. Non-new converted rows receive `triaged_at`; legacy status/provenance fields and their timestamps are removed. Unknown user fields are preserved. Clean v2 rows are unchanged, including during a mixed migration, and later library arrivals do not trigger another state migration.

IndexedDB version 2 adds a namespaced `backups` store. Migration commits the original raw state JSON there before enqueueing any conversion; offline older caches without raw text are serialized before conversion. Failure to retain this backup blocks migration. Settings exports it separately via `getPreV2Backup()`. Backups survive Lock and are not encrypted by the vault. The durable state write includes migration time and library fallback context. Every conflict re-converts the fresh remote and merge ancestor before per-field merging, so conversion itself never outranks concurrent user edits. An edit queued during PUT is rebased onto what reached the repository. Migration queue entries explicitly carry `createOnly: true`; legacy recovery entries without the flag retain create-only semantics. A real `saveQueue` upgrades the entry to editable intent.

## Module map and contracts

- `index.html`, `styles.css`: semantic three-column shell, dialogs, drawers, resize handle, dark/light themes. Desktop widths: library 20vw; by default the reader and notes share the rest equally (`--notes-width: calc((100vw - var(--sidebar-width)) / 2)`). A dragged notes width (22–55vw) is remembered per device under `reading-notes-width-v2`.
- `js/app.js`: bootstrap, active article, settings/backup, progress transitions, guarded keyboard routing, overflow/View controls, relative sync clock, six-second toast/Undo handling, body search and integration. Notes hydration enumerates existing note files, then fetches four at a time. Edition is checked after initialization, on successful sync, every 30 seconds when the local date changes, and on visibility restoration. Stale connection/date results are ignored; unchanged editions do not replace live controls. Highlight, agreement and connection Undo target their original article after navigation.
- `js/reader.js`: markdown source layout, persistent quote anchoring, selection toolbar, note editors below the highlighted sentence and highlighted-passage drag payloads. `onDelete(highlight)` delegates immediate persistence and Undo to the app; selection actions reuse canonical offsets and quote data.
- `js/library.js`: `Library({root,onOpen,onStar,onProgress,onTag})`; `render(items,{activeId,query,tag,starredOnly,progress,withNotes,shortOnly,source,bodies})`, `move(delta)`, `openFocused()`. Four progress groups sort newest added first; With notes sorts globally by notes updated_at. Rows derive badges from note text, show one untruncated domain chip and a Reading position bar. Search remains titles/authors/handles/tags/bodies.
- `js/notes.js`: `NotesPane({root,getItem,onChange,onOpen,onRemoveLink,onJump,notify})`; `setArticle(item,notes)`, `updateMargins(highlights)`, `updateLinks(links)`, `focus()`, `appendQuote(quote)`, `reviseQuote(quote)`. Only user content: long markdown notes, reading-order highlights, kept links. Known links use live library titles and native click/Enter navigation; missing links are labelled and remain removable. `reviseQuote` holds a local unsaved draft, rebases it onto same-article reconciliation, saves on substantive input, and cancels untouched drafts on Esc without a write. Ordinary quote append remains immediate-save.
- `js/model.js`: DOM-free migration and library-field fallbacks. `collectionOf(record)` sorts records into Library, Papers or Books & textbooks (`collection` field first, then `source_type`). `splitArrivals` remains only for migrating older state.
- `js/edition.js`: DOM-free `localDate`, defensive `parseEdition`, `editionMinutes`, `editionDone`, `findMargin`, `setStillAgree` and `undoStillAgree`. Valid parts survive unknown slugs, missing explanations or malformed sections; slots and slugs are deduplicated and sorted long/short/archive. Bad JSON/top-level/date mismatch makes the edition unavailable, with one warning per malformed fetch. Minutes reuse 2.1 fallbacks. Completion requires at least one pick and every pick Finished/Let go. Margin lookup excludes missing, deleted and tombstoned highlights; agreement Undo owns only that field.
- `js/edition-view.js`: `EditionView` renders masthead, pick rows/reasons/progress, the user margin quote/note, and untriaged edition arrivals. Selection uses j/k/Enter; triage, article opens, agreement/revision and completion navigation delegate to app callbacks. Missing editions hide the tab; no extra mode-switch key is introduced.
- `js/connections.js`: pure deduplicating `connectionDecision(notes,action,link)` and targeted `undoConnection(current,before,after,slug)`. Keep clears hidden membership. Undo restores only the target slug when not superseded, preserving unrelated note text, highlights and connection decisions.
- `js/progress.js`: DOM-free automatic-finish threshold and Undo/re-arm tracker, instantiated per article by the app.
- `js/bot.js`: pure `parseBotSummary(markdown)` and `isSummaryStale(summary,notes)`, plus `BotBox({root,getItem,onKeep,onUnkeep,onHide,onOpen}).render(markdown,notes)`. Parses scalar front matter, block/flow connection maps and markdown links outside code fences. Known suggestions resolve library titles; unknown ones are labelled and cannot Keep. Kept suggestions show Kept ✓ and Unkeep. Show hidden toggles presentation only, persists through notes renders, and resets when the article's summary changes/clears. Text uses the safe renderer; missing writers use Reading bot. The box is after the body and absent on 404, never in Your notes.
- `js/markdown.js`: `renderMarkdown(text)` returns escaped, safe HTML. No raw HTML execution; URL schemes are allowlisted. Supports headings, paragraphs, lists, block quotes, code, emphasis, links and images; internal article links stay local.
- `js/store.js`: `ReadingStore extends EventTarget`; `init() -> {library,state,meta,queue}`, `getArticle`, `getNotes`, `getSummary`, `getEdition(date,{refresh})`, `getNoteSlugs`, `getPreV2Backup`, `getSearchIndex`, `getAsset`, `saveState`, `saveQueue`, `saveNotes`, `flush`, `exportData`, `importData`, `testConnection`. `change` events expose local/queued/sync/error states. Edition reads use the existing independent-value cache and explicit awaited refresh, not a second network client or background event. Initial application access refreshes even cached 404s; 404 is quiet, malformed editions are safely parsed, transport errors retain cached content and report connection status. Pure merge functions support deterministic verification; writes remain restricted to user state, queue and notes.
- `js/demo.js`: six original fictional articles and legacy migration examples, three queued records, four additional Arrivals with metadata omissions, 27 pile records, two old/never-opened Keepers, and one hand-made Edition using existing slugs and an existing margin highlight. Its publication date/time follows demo startup and new local-day access. Read-only fixtures refresh; existing `demo:v2` state, queue and notes remain untouched. No namespace bump is needed; v1 cleanup remains.
- `js/vault.js`: DOM-free WebCrypto envelope operations and validation. `createVault(payload,password)` returns `{vault,payload,dek}`; password/PRF unlock returns `{payload,dek}`. Immutable slot addition/removal and password replacement retain the DEK. Raw DEKs are 32-byte arrays kept only in memory or inside the encrypted remembered record.
- `js/passkey.js`: dynamic-hostname WebAuthn PRF registration, optional second assertion, credential-specific PRF evaluation, feature detection and default device labels.
- `js/session.js`: serialized `saveRemembered`, `loadRemembered`, and `deleteRemembered` operations. Separate `reading-terminal-session` database avoids changing the reading-cache schema.
- `js/vault-api.js`: cache-bypassing public vault fetch and restricted site-repository `vault.json` publication. Security commits three-way merge slots by id against the latest SHA, retry 409/422 once, preserve concurrent deletions, reject concurrent password replacements and never merge different vault identities/payloads.
- `js/auth.js`: boot/lock/setup routing, in-memory session ownership, Security UI and remembered-device lifecycle. The app receives credentials directly through `ReadingStore(settings)`, never through settings persistence.
- `sw.js`: network-first public app-shell cache with an offline fallback. GitHub API responses, vault.json, articles, notes and tokens never enter this service-worker cache. Vault requests, including direct navigations, bypass shell routing.
- Reconciliation events: `state-updated {state}`, `queue-updated {queue}`, `notes-updated {slug,notes}`, `article-updated {slug,markdown}`, and `summary-updated {slug,markdown}`. Queue events include an independent copy of the complete queue record. The app keeps newer event results when an article-opening request is still awaiting its other files. `dispose()` releases a replaced store's debounce, blob URLs and database handle.
- User navigation pushes history; initial/deep-link restoration replaces it. Back/Forward restore articles or Library without adding history. Demo hashes retain `#demo&article=…`. Private assets use authenticated blob fetching; PDFs receive `application/pdf`; Open PDF/Open source live in the reader menu. Items without body images get an `images[]` strip. Dashed `.bot-content` boxes distinguish intake and end-article bot output from user notes. Generated titles are italic; density/theme remain device-local. Long notes grow/shrink on input, load, quote append and width/font changes.
- Desktop top bar exposes Edition (when available) / Arrivals / Up next / Library. Mobile retains Library/title/Notes/⋯ and adds the same one-tap modes beneath it. Mode-specific keyboard routing runs only outside editors, auth screens and dialogs. K means Keep while triaging; otherwise j/k navigate, including Edition picks.

## Select → highlight → note → drag state machine

Idle → a non-empty reader source selection stores a range and offers Highlight / Send to notes / Copy. `h` and the floating Highlight action share one operation. There is no contextmenu handler; right-click belongs to the browser. `selectionchange` supports touch selections; actual toolbar dimensions and `visualViewport` bounds keep it above the selection and inside the visible viewport, including zoom/scroll changes. Pointer-down on actions preserves selection. Selection spanning rendered text is converted to canonical paragraph/text offsets, quote and surrounding context. Exact quote and context choose an anchor on re-render; paragraph is a ranking hint, not an absolute dependency. Missing anchors are visibly reported and retained, never silently deleted.

Highlight creation → the note editor opens below the sentence the highlight ends in, with keyboard focus. Text flows normally at about 1.6 line height; nothing is measured. Each paragraph is split into `.source-line` segments only at those sentence ends (`sentenceEnd`: the first `.`, `!`, `?` or `…` after the highlight's end that is followed by a capital, digit, quote or the paragraph end, plus closing quotes and spaces; headings and code blocks use their end). Each segment ends in a `.line-gap`; empty gaps are hidden, so the paragraph reads as one until a note opens space. Notes for highlights ending in the same sentence stack in reading order. The editor is one auto-growing textarea: typing updates the note without rebuilding the article. Escape closes editing, and Backspace on an empty note keeps the highlight. Delete offers Undo. Stored anchors (quote, prefix, suffix, para, start) are unchanged.

Soft markdown line breaks are normalized before measurement; mixed inline fonts use a line-height threshold rather than a font-dependent glyph top. Text surrounding inline images becomes separate source paragraphs, preserving both image display and text anchoring. `Reader.getHighlights()` supplies resolved reading-order offsets, including for older highlights without a stored `start`. Mobile drawers make closed panes and the covered reader inert to keyboard focus.

Highlighted text is draggable as `application/x-reading-highlight` plus `text/plain`, with a quote drag ghost. The notes pane accepts only an actual highlight drag, shows a drop target, and appends `\n\n> quote` after trimming trailing whitespace (one empty line). The same canonical notes object updates the reader and the read-only reading-order margin collection. Keyboard/touch users can also send a highlight to notes via its small action control.

## Sync and conflict handling

GitHub Contents API calls include a fine-grained bearer token and branch. Reading PUTs are restricted to `user/state.json`, `user/queue.json`, and safe `user/notes/*.json` paths. Reads cache content and SHA; state reads also retain original raw JSON for migration backup. Write queue entries include local content, the merge base and optional migration/create-only context. Saves are durable before the network write. The paced sync (`flush({drain:false})`) starts 2 s after the last edit and at least 10 s after the last commit, sends each queued file once and hands later edits to the next paced sync; blur, hidden visibility and online events drain everything. A 429, or a 403 carrying `retry-after`, `x-ratelimit-remaining: 0` or a rate-limit body, sets `_retryAt`; flushes, paced syncs and `refreshNotes` wait it out. `refreshNotes(slug)` re-reads one notes file; the app calls it on focus, visibility restoration and every 30 s, except within 5 s of a local note edit. Unsynced changes survive reload; requests serialize per store. Flush cannot publish legacy recovery entries before initialization backs them up and converts them.

Before writing, fetch the current remote SHA. Three-way merge against the queued base: highlight ids use updated_at last-write-wins and tombstones; state uses field timestamps; unchanged sides do not conflict. Concurrent differing long-note edits preserve both with an explicit conflict marker, newer first. A 409/422 re-fetches and retries boundedly; authentication, rate limits, offline errors and exhausted conflicts leave the durable queue intact with an actionable status. Never PUT bot or article paths. A completed sync must not overwrite edits queued while a request was in flight.

Queue merge: when the remote queue equals the saved base, the complete local order wins. Otherwise keep remote order, remove ids locally removed relative to base, and append local additions absent remotely. Unchanged local copies do not resurrect remote removals. Remote `arrivals_since` wins and independent metadata survives. Concurrent overflow takes the first ten of the remote-priority merged order; excess local additions remain in Library. Oversized input files are rejected rather than rewritten. Refreshes preserve editable pending queues; create-only entries adopt remote content without a PUT. Queue changes during GET/PUT are rebased onto the sent result and flushed afterward, including uncontested in-flight reorders.


Kept and hidden connections use three-way slug membership: removals relative to the ancestor beat an unchanged copy; independent additions survive. Unkeep, Remove and Hide Undo therefore persist after sync without resurrecting removed links. Duplicate memberships are normalized. Highlight merging treats `still_agree_at` independently of quote/note/anchor changes, so agreement and Undo preserve concurrent note edits. `notes_summary_len` has no sorting role. Library badges/With notes use enumerated user note files, never bot summary length or progress.

Flush awaits outstanding user-file cache reconciliation before taking a write snapshot. This prevents a failed offline read from retaining a rejected repository-check promise into the first reconnect flush. An unavailable remote backup is explicitly marked `complete: false`, lists warnings, and downloads with `PARTIAL` in its filename; cached work remains exportable without falsely claiming a complete remote backup.

Settings order is Security, Backup, Connection, then collapsed Advanced token connection. Regular export contains available state, queue and notes, never credentials or source articles; import merges and cannot replace an existing queue. The separate pre-v2 export is the retained original state file. Private assets are authenticated and exposed as blob URLs without tokens in URLs. Demo exercises the same persistence locally without network requests. Private successful initialization/flush emits `synced`; the UI renders relative time every 15 seconds and exact time in `title`. Queued/error/demo states are not called successful private sync.

## UNLOCK security and lifecycle

### Public vault and offline guessing

`vault.json` is public, including its Git history. Its random 256-bit DEK encrypts the JSON connection payload with AES-256-GCM; payload AAD is the UTF-8 `vault_id`. Exactly one password slot wraps the same DEK using a non-extractable AES-256-GCM key derived with PBKDF2-SHA256, at least 600,000 iterations, and a fresh salt of at least 16 bytes. Lower iteration counts are refused. Each wrap binds `vault_id + ":" + slot.id` as AAD. IVs are independently random 12-byte values; ids and key material use `crypto.getRandomValues`.

The password only protects against offline guessing through its entropy and the PBKDF2 cost. The 12-character floor and strength hint are not a security guarantee: use **4–5 random words**, not a quotation or familiar phrase. Wrong passwords, malformed password envelopes and failed authentication share “That password did not unlock the library.” Setup clears both password fields after every attempt, but retains the GitHub token on validation/network/GitHub errors so it can be retried; success clears all three. Change password clears the current, new and confirmation fields on both success and error, including mismatches.

Each passkey slot uses its own 32-byte PRF salt. A 32-byte WebAuthn PRF result derives the wrapping key through HKDF-SHA256, using decoded vault-id bytes as salt and `reading-terminal-vault-v1` as info. The authenticator's private key and underlying PRF secret never leave the authenticator; its evaluated PRF result is necessarily returned to the browser for key derivation and is not persisted. RP id is the current hostname. User verification and resident credentials are required. A create-time PRF result is used directly; supported authenticators that omit it require a second prompt. Unsupported PRF commits no slot and leaves password unlock available.

Local WebAuthn checks use `http://localhost:<port>`, not `127.0.0.1`: the latter is not a valid WebAuthn RP id. `SecurityError` reports “Passkeys are not available on this address.” separately from unsupported PRF and prompt cancellation. The Chrome CDP smoke uses `ctap2_1`, `internal`, and `hasPrf: true` and requires registration, an encrypted vault commit, Lock and successful PRF unlock; an unsupported fallback is not a passing result. Physical authenticators remain a separate verification limit.

There is **no authentication server**. Challenges are random and assertion signatures are not verified against a server challenge. This is intentional: decryption depends on the secret PRF output, not on trusting an assertion signature or a client-side “authenticated” boolean.

### Device trust and revocation

Anyone possessing the unlocked GitHub token has **Contents read/write on both reading-data and reading-terminal**. Site code, the GitHub account, browser extensions and all scripts sharing the Pages origin must be trusted. Other projects on `tunaissacoding.github.io` share its origin/RP scope. XSS, malicious same-origin code, a compromised browser or an unlocked device can use or steal an unlocked token. CSP and safe markdown rendering reduce exposure but do not turn browser JavaScript into a hardware security boundary.

“Remember this device” stores a structured-cloned **non-extractable AES-GCM CryptoKey** in IndexedDB beside encrypted `{vault,payload,dek}`; vault identity and update timestamp are authenticated metadata. Non-extractable means WebCrypto cannot export the key: same-origin code can still use it to decrypt. Remembering is a convenience for a trusted browser profile, not another password or protection against a compromised profile. Turning it off deletes the device record and keeps credentials in memory only; no sessionStorage credentials are used.

Remembered sessions connect first, including offline. A background network-only vault check invalidates a different `vault_id`, deletes the record and locks the app, even if a security operation is still running. A delayed operation cannot restore a superseded session. Older same-identity Pages publications do not roll back a newer locally committed vault. Password/passkey commits update the in-memory vault and remembered metadata.

Lock gives sync up to 1.5 seconds, aborts requests, clears credentials/reader content, revokes asset URLs and deletes the namespace's content cache. **Unsynced edits, merge bases and the pre-v2 backup remain** in the durable queue/recovery journal and backup store. They are not encrypted by the vault. Export before clearing browser data or retiring a device.

Removing a passkey or changing the password changes future unlocks against the current vault, not copies already saved by an attacker or Git history. Neither revokes a leaked token or an existing remembered session with the same vault identity. Passkey removal hides the row optimistically and waits for its six-second Undo notice to expire before publishing. Undo restores the row without a commit; pending removals cancel on Lock/session changes. Expired removals serialize behind other security operations; commit failures restore the row. For actual revocation, **delete/revoke the token on GitHub and run `#replace` with a new token and vault**. The separate replacement screen requires exact typed REPLACE; setup cannot overwrite an existing vault. Old passkeys stop working against the new vault. Background invalidation is eventual and requires seeing the new publication. An offline device cannot observe revocation until it reconnects.

### Setup and connection boundaries

A 404 public vault response opens setup (or the old manual-token connection when one exists); other load errors show Retry rather than treating failure as first use. The lock screen presents Password, Unlock, an available passkey button, Remember this device and Explore the demo; collapsed Other options contains setup and replacement links. Demo is explicit with a separate `demo:v2` namespace; loading `#demo` or a demo article hash opens that library before restoring a remembered session or fetching the vault. Demo startup deletes only `demo:v1` records from cache, queue and backups plus legacy demo localStorage keys, including the pending journal; real-library namespaces are untouched. `#setup` never replaces; `#replace` has its own screen and exact REPLACE gate. The token only goes to `api.github.com` in Authorization headers; the password and plaintext DEK are never transmitted. Setup checks the private data repository, obtains the site file SHA and publishes encrypted JSON with message `Update reading vault`. A missing site file is distinguished from denied repository access.

Export/import contains user state, queue and notes, never the token, DEK, vault or remembered-device key; pre-v2 export contains original state only. Legacy token settings stay under Advanced; vault unlock removes the old saved token. Auth screens isolate the background and suppress reading shortcuts. Inputs, textareas, selects, contenteditables and textbox editors bypass global reading shortcuts. Esc closes overlays/menus/drawers before closing the article. Menus close on outside pointer-down; Text-node event targets are normalized.

## Verification plan

Run `node --check` for all JavaScript and `node --test tests/`. Serve the static app at localhost and run the full headless system-Chrome suite against fictional GitHub fixtures. Cover exact migration writes and backup, concurrent edits, progress/Undo, bot decisions, filters, interlinear geometry and existing auth/security regressions. Inspect desktop/mobile surfaces directly. Record only observed results and remaining limits in REPORT.md; Chrome emulation does not establish native iPhone/iPad Safari support.
